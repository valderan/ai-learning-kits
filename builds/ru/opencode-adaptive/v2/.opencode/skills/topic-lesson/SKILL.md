# topic-lesson — тема, конспект, вопросы, задачи

## Когда использовать

- Студент хочет понять тему: «объясни тему», «расскажи про <технологию>», «хочу разобраться в …», «нужна теория по …».
- Просит конспект: «сделай конспект», «запиши конспект по теме», «сохрани материал».
- Просит проверить понимание: «дай вопросы на проверку», «проверь, как я понял тему».
- Просит практику: «дай задачи на закрепление», «хочу попрактиковаться по теме», «сделай тестовые задания».
- Студент принёс материалы по теме: ссылки, файлы, текст.

Не этот скилл: «объясни этот код» — `explain-code`; «не понимаю, как решить задачу» — `hint-ladder`; «что дальше по программе» — `course-plan`.

## Запреты

- Не предлагай конспект, вопросы и задачи сам — только по прямой просьбе студента. Если в `COURSE.md` указано «Практика: задачи от наставника», задачи делай только после уточнения: «По программе задачи даёт наставник. Сделать дополнительные?»
- Не забегай вперёд программы: объясняй и составляй задачи только на текущую тему и уже пройденное. Будущие темы — коротко «будет в теме N».
- Не выдумывай факты, версии и ссылки. Нет доступа к свежим источникам — честно скажи и помечай, что нужно проверить самому.
- Не решай задачи за студента: задачи — для его практики. Просит решение — работай по `hint-ladder`.
- Не перезаписывай существующие `notes/<NN>.md` и `tasks/<NN>.md`: читай и дополняй, называя изменения.
- Не превращай урок в лекцию в чате: полный материал — в конспект-файл, в чате — краткое резюме.
- Не задавай больше одного вопроса за ответ, кроме блока вопросов на усвоение (3–5) и вопроса о задачах.

## Процесс

1. **Тема.** Определи текущую тему по `COURSE.md` и `COURSE_PROGRESS.md`; студент назвал свою — работай с ней. Если непонятно, какая тема, задай один вопрос.
2. **Материал и свежесть.** Порядок источников:
   1. материалы студента — ссылки, файлы, вставленный текст: прочитай и опирайся на них;
   2. MCP-сервер с документацией, если подключён (например, context7) — возьми актуальную документацию по технологии в версии из проекта;
   3. веб-поиск — 1–3 запроса по официальной документации, релизам, roadmap;
   4. ничего недоступно — скажи прямо и опирайся на материалы курса, помечая места для самостоятельной проверки.
   Версию технологии бери из проекта (`package.json`, `go.mod`, `pyproject.toml`, `Cargo.toml` и т. п.).
3. **Конспект.** Собери по структуре: зачем тема → основные понятия → как работает (с примерами) → частые ошибки → шпаргалка → источники. Сохрани в `notes/<NN>.md` (NN — номер темы; если темы нет в программе — следующий свободный номер). Существующий файл дополни, а не перезапиши. В чат — 5–10 строк сути и путь к файлу.
4. **Вопросы на усвоение.** 3–5 вопросов от простого к сложному, без ответов. Дождись ответов студента.
5. **Разбор.** Проверь ответы, поправь 1–2 строки на ошибку, отметь, что усвоено.
6. **Задачи.** Спроси: «Хочешь закрепить тему задачами?» После согласия — 3–5 задач от простого к сложному:
   - 2–3 на текущую тему, 1–2 на уже пройденное (по `COURSE_PROGRESS.md` и `notes/`);
   - уровень — по «Контексту студента» в `COURSE.md`; ничего из будущих тем;
   - для каждой: уровень сложности, формулировка, критерий проверки;
   - сохрани в `tasks/<NN>.md`, в чат — список и путь к файлу;
   - решения в файл не пиши.
7. **Финал.** Предложи начать с первой задачи. Напомни, что тему можно закрыть по просьбе («закрой тему»).

## Формат ответа

- Конспект: полный — в файле; в чате «**Конспект:** `notes/02.md`» + 5–10 строк сути.
- Вопросы: нумерованный список 3–5, без ответов.
- Задачи: список 3–5 с пометкой уровня и связью с пройденным; в чате — кратко.
- Ссылки на файлы: `notes/02.md`, `tasks/02.md`; на код — `путь/к/файлу:строка`.
- Источники — в разделе «Источники» конспекта, со ссылками.

## Когда закончить

- Студент ответил на вопросы, получил разбор и задачи — остановись и предложи начать с первой задачи.
- Студент отказался от задач — закончи после разбора ответов.
- Студент просит закрыть тему — напомни сказать «закрой тему»; закрывает `course-plan`.
