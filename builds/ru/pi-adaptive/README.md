# pi-adaptive — учебный режим для pi

Учебный режим для pi: наставник, который подсказывает, проверяет и объясняет, но **код пишет студент**.

Отличия от OpenCode-версии:

- pi не умеет переключать агентов сессии, поэтому персона живёт в `.pi/APPEND_SYSTEM.md` и включается сразу при запуске в проекте — отдельного «primary-агента» и переключателя нет;
- pi по умолчанию не спрашивает подтверждений перед инструментами, поэтому права из OpenCode-агента перенесены в **правила** `pi-guard` в `.pi/settings.json` (правки — с подтверждением, тесты — без); сам guard включается и выключается глобально: `/guard enable|disable|toggle`;
- в наборе нет субагентов, расширений и скриптов — только статические файлы;
- с OpenCode-версией набор не синхронизируется и живёт отдельно — это осознанное решение.

## Состав

```
pi-adaptive/
├── README.md                # этот файл
└── .pi/
    ├── README.md            # подробная инструкция студенту
    ├── APPEND_SYSTEM.md     # персона наставника (включается при старте)
    ├── settings.json        # правила pi-guard для учебного проекта
    ├── skills/
    │   ├── hint-ladder/     # подсказки по ступеням
    │   ├── code-review/     # ревью решения
    │   ├── debug-coach/     # разбор ошибки
    │   ├── explain-code/    # объяснение кода
    │   ├── course-plan/     # работа с программой курса и прогрессом
    │   └── topic-lesson/    # тема: конспект, вопросы, задачи
    └── templates/           # примеры COURSE.md + COURSE_PROGRESS.md
        ├── go/
        ├── python/
        ├── typescript/
        └── css/
```

## Установка

```bash
cp -R builds/ru/pi-adaptive/.pi /путь/к/учебному/проекту/
cd /путь/к/учебному/проекту
pi
```

При первом запуске pi спросит доверие проектным файлам — `.pi/APPEND_SYSTEM.md` и `.pi/skills/` входят в защищённые ресурсы. Ответь «да», и режим включён. Полезные варианты:

- `/trust` — запомнить решение для папки (решение родительской папки покрывает вложенные проекты);
- `pi --approve` — довериться на один запуск;
- `pi --no-approve` — запустить **без** учебного режима;
- `defaultProjectTrust: "always"` в `~/.pi/agent/settings.json` — для выделенной учебной машины (в поставку не входит, это глобальная настройка).

Если папка скопирована в уже запущенную сессию — `/reload`.

## Зависимости

- pi (проектные `.pi`-ресурсы поддерживаются стандартно).
- `pi-guard` — **опционально**, только для подтверждений действий: `pi install npm:pi-guard`. Без него секция `guard` в `settings.json` игнорируется, всё остальное работает.

## Отключение

- `pi --no-approve` — один запуск без режима.
- Переименовать/удалить `.pi/APPEND_SYSTEM.md` — выключить персону, скиллы оставить.
- Удалить `.pi` — выключить всё.

## Проверка

Быстрый сценарий (подробный протокол — в `.pi/README.md`):

1. Скопировать `.pi` в тестовый проект, запустить `pi --approve`, убедиться, что в стартовом выводе загружены скиллы.
2. «я застрял» → агент отвечает «Подсказка 1 из 4» и не пишет готовый код.
3. В проекте с `COURSE.md` — в начале сессии видны чтения `COURSE.md` и `COURSE_PROGRESS.md` до первого ответа.
4. `/guard list` → текущее состояние и правила; `/guard enable` → правка файла агентом запрашивает подтверждение, `npm test` — нет.

## Ограничения

- Режим всегда включён в проекте, где лежит `.pi/APPEND_SYSTEM.md`; это не переключатель, а среда учебного проекта.
- Чтение `COURSE.md` — действие модели по инструкции, а не хук pi: агент делает его первым ходом, но гарантии уровня расширения нет.
- Проверка актуальности программы зависит от доступа pi к веб-поиску: нет доступа — агент честно скажет и предложит источники для самостоятельной проверки.
- Права без `pi-guard` держатся только промптом: pi не спрашивает подтверждений сам.
