# Учебный режим для pi — инструкция студенту

Эта папка превращает pi в наставника: агент подсказывает, проверяет и объясняет, но код пишешь ты. Режим **включён всегда**, пока в проекте лежит `.pi/APPEND_SYSTEM.md` — отдельно включать ничего не нужно.

## Что внутри

| Файл | Зачем |
|---|---|
| `APPEND_SYSTEM.md` | Персона наставника. pi подмешивает её в system prompt при каждом запуске — поэтому режим работает с первого сообщения |
| `skills/` | Шесть скиллов, которые агент загружает по ситуации |
| `templates/` | Примеры `COURSE.md` и `COURSE_PROGRESS.md` для Go, Python, TypeScript и CSS |
| `settings.json` | Правила `pi-guard` для этого проекта; сам guard включается и выключается глобально |
| `README.md` | Этот файл |

## Быстрый старт

1. Скопируй папку `.pi` в корень учебного проекта.
2. Запусти `pi` в этом проекте.
3. При первом запуске pi спросит, доверять ли проектным файлам, — ответь «да». Без доверия `.pi` не загрузится: это защита pi от чужих конфигов.
4. Проверь, что режим работает: спроси «кто ты?» — агент ответит как наставник и не начнёт писать код за тебя.

Полезно знать:

- `/trust` — запомнить решение о доверии для этой папки, чтобы больше не спрашивало. Решение для родительской папки (например `~/learning`) покрывает все вложенные проекты.
- `pi --approve` — довериться на один запуск.
- `pi --no-approve` — запустить pi **без** учебного режима (проектные `.pi`-файлы игнорируются).
- Если копируешь `.pi` в уже запущенную сессию — выполни `/reload`.

## Программа курса и прогресс

В корне проекта могут лежать два необязательных файла:

```
COURSE.md           # что и зачем учим: цель, контекст, модули и темы, материалы
COURSE_PROGRESS.md  # строка «Сейчас: N. Тема» и чек-лист пройденного
```

Агент читает их в начале сессии и дальше ведёт подсказки в рамках текущей темы, не забегая вперёд. Если файлов нет — он один раз предложит их создать и не будет настаивать.

Три способа завести файлы курса:

1. **Дать программу агенту.** Скажи: «вот моя программа обучения» и пришли её текстом, файлом или ссылкой. Агент разберёт её, проверит актуальность по официальным источникам (если есть доступ к веб-поиску), покажет черновик и создаст файлы.
2. **Попросить курс с нуля.** Скажи: «хочу научиться NestJS». Агент сначала спросит про твой уровень, цель и время, затем предложит 2–3 вектора обучения — и после твоего выбора создаст файлы.
3. **Взять готовый пример.** Скопируй `.pi/templates/<язык>/COURSE.md` и `COURSE_PROGRESS.md` в корень проекта и замени темы на свои.

Как устроен прогресс:

```markdown
Сейчас: 2. Функции

- [x] 1. Переменные и типы
- [ ] 2. Функции
- [ ] 3. map и filter
```

- Текущая тема — из строки `Сейчас`, а если её нет — первый пункт без `[x]`.
- Тему закрывает агент, но **только по твоей прямой просьбе**: «закрой тему», «отметь, что я прошёл». Он поставит `[x]` и перенесёт `Сейчас` на следующий пункт.
- Программу можно обновить в любой момент: «обнови программу», «проверь актуальность». Агент предложит правки; уже пройденные темы останутся нетронутыми.

### Конспекты и задачи

- `notes/<NN>.md` — конспекты по темам: агент создаёт по просьбе «объясни тему» или «сделай конспект».
- `tasks/<NN>.md` — задачи для самоподготовки: 3–5 штук от простого к сложному, только на текущую и уже пройденные темы.
- Агент не предлагает конспекты и задачи сам — только по твоей просьбе. Если в `COURSE.md` стоит «Практика: задачи от наставника», задачи по курсу ты делаешь с наставником, а дополнительные агент сделает только после уточнения.

## Скиллы

Агент подхватывает их сам по описанию ситуации. Можно вызвать вручную: `/skill:<id>`.

| Скилл | Когда срабатывает |
|---|---|
| `hint-ladder` | «застрял», «не получается», «не знаю, как дальше» — подсказки по ступеням, от направления до готового решения |
| `code-review` | «проверь мой код», «что не так с решением» — разбор без переписывания |
| `debug-coach` | ошибка, стектрейс, «падает», «выдаёт не то» — разбор ошибки без готового фикса |
| `explain-code` | «объясни этот код», «что тут происходит» — разбор по блокам или построчно |
| `course-plan` | программа курса: разобрать программу, составить курс, обновить её, закрыть тему |
| `topic-lesson` | «объясни тему», «сделай конспект», «дай вопросы на проверку», «дай задачи на закрепление» — конспект в `notes/`, задачи в `tasks/` |

## Guard — подтверждения действий (по желанию)

Состояние guard — это **глобальная настройка pi-guard** (хранится в `~/.pi/agent/settings.json`), а `.pi/settings.json` задаёт только правила для учебного проекта: правки и запись — с подтверждением, тесты и программа курса — без.

- `/guard list` — посмотреть текущее состояние и правила;
- `/guard enable` — включить подтверждения, `/guard disable` — выключить, `/guard toggle` — переключить.

Свободный режим (pi ничего не спрашивает): `/guard disable`. Тогда правило «код пишешь ты» держится только на персоне агента. Если pi-guard установлен, а его глобальные настройки пусты, он по умолчанию включён — потому начни с `/guard list` и выбери режим сам.

Что меняется при включённом guard:

- правки и запись файлов — с подтверждением;
- запуск тестов и программы курса (`npm test`, `node`, `python`, `pytest`, `go test`, `cargo test` и т.д.) — без подтверждения;
- чтение — без подтверждения;
- остальные команды — с подтверждением.

Правила работают, только если установлено расширение `pi-guard`: `pi install npm:pi-guard`. Без него `settings.json` просто игнорируется — и всё остальное в наборе продолжает работать.

## Проверка, что режим работает

- Напиши «я застрял» — агент должен загрузить `hint-ladder` и выдать «Подсказка 1 из 4» без готового кода.
- Напиши «проверь мой код» — получишь ревью со ссылками вида `файл:строка`, без переписанного решения.
- Открой `/` и убедись, что в списке команд есть `/skill:hint-ladder`, `/skill:code-review`, `/skill:debug-coach`, `/skill:explain-code`, `/skill:course-plan`.
- В начале сессии в проекте с `COURSE.md` в транскрипте должны быть видны чтения `COURSE.md` и `COURSE_PROGRESS.md` — до первого ответа.

## Если что-то не так

| Симптом | Что делать |
|---|---|
| Агент ведёт себя как обычный ассистент | Проверь, что режим включён: запусти pi без `--no-approve` и подтверди доверие; затем `/reload` |
| Нет команды `/skill:...` | Убедись, что папка `.pi/skills` целиком скопирована и проекту выдано доверие |
| Агент не сослался на программу | Напиши «прочитай COURSE.md и COURSE_PROGRESS.md» |
| Прогресс не отмечается без просьбы | Так и задумано: скажи «закрой тему» |
| Хочу обычный режим работы | `pi --no-approve`, или `/guard disable`, или убери `.pi/APPEND_SYSTEM.md` (переименуй, чтобы вернуть) |

## Полное выключение режима

- На один запуск: `pi --no-approve`.
- Навсегда в этом проекте: удали или переименуй `.pi/APPEND_SYSTEM.md` — персона исчезнет, скиллы останутся доступны.
- Полностью: удали папку `.pi` из проекта.
