# AGENTS.md — инструкции для агентов, работающих над проектом

## Что это за проект

`ai-learning-kits` — наборы учебного режима для AI-агентов: наставник, который подсказывает, проверяет и объясняет, но **код пишет студент**. Сборки лежат в `builds/ru/` (русские) и `builds/en/` (английские) и ставятся копированием в учебный проект — без глобальной установки. Позже появится инсталлятор на Python для macOS, Linux и Windows.

| Сборка | Для кого | Как ставится |
|---|---|---|
| `builds/ru/pi-adaptive` | pi | `cp -R builds/ru/pi-adaptive/.pi <проект>/` |
| `builds/ru/all-adaptive` | агенты с `AGENTS.md` и `.agents/skills/` | `cp builds/ru/all-adaptive/AGENTS.md <проект>/` и `cp -R builds/ru/all-adaptive/.agents <проект>/` |
| `builds/ru/opencode-adaptive/v1` | OpenCode 1.x | `cp -R builds/ru/opencode-adaptive/v1/.opencode <проект>/` |
| `builds/ru/opencode-adaptive/v2` | OpenCode 2.x | `cp -R builds/ru/opencode-adaptive/v2/.opencode <проект>/` |

В `builds/en/` лежат полные английские копии тех же сборок с той же структурой и путями; меняются они синхронно с русскими (см. правила работы).

## Инварианты, которые нельзя ломать

1. **Сборки самодостаточны.** Каждую можно скопировать в проект как есть; в рантайме сборки не зависят друг от друга. Внутренние ссылки между README сборок допустимы, внешние ссылки на сторонние проекты и репозитории — нет.
2. **Шесть скиллов в каждой сборке:** `hint-ladder`, `code-review`, `debug-coach`, `explain-code`, `course-plan`, `topic-lesson`. Правя скилл, обнови его во всех четырёх вариантах (pi, all, opencode v1, opencode v2) и подними `metadata.version` в каждом.
3. **Персона — одна на сборку, правила одинаковые:** принципы наставника, программа курса, маршрутизация скиллов, формат ответа. Различаются только пути: `.pi/…`, `.agents/…`, `.opencode/…`.
4. **У агентов OpenCode v1 и v2 тела должны совпадать байт-в-байт.** Различается только frontmatter: `permission` (объект) в v1, `permissions` (список `action`/`resource`/`effect`) в v2. Правь оба и сверяй.
5. **Соглашения скиллов:** имя = имя папки (латиница через дефис), `description` на русском с фразами-триггерами, ≤1024 символов, пять разделов строго в порядке: «Когда использовать», «Запреты», «Процесс», «Формат ответа», «Когда закончить».
6. **Файлы курса** в учебном проекте: `COURSE.md` (цель, контекст, строка `Практика: …`, программа, материалы, `Актуализировано`) и `COURSE_PROGRESS.md` (`Сейчас: N. Тема` + чек-лист). Шаблоны — в `<сборка>/templates/<язык>/`. Темы в `COURSE.md` и чек-лист в `COURSE_PROGRESS.md` должны совпадать, а `Сейчас` — указывать на первый пункт без `[x]`.
7. **Конспекты и задачи** агент создаёт только по просьбе студента: `notes/<NN>.md` и `tasks/<NN>.md` в корне учебного проекта. Решения задач в `tasks/` не хранятся; задачи — 3–5, от простого к сложному, только на текущую и пройденные темы.
8. **Без брендинга.** Никаких названий школ, ссылок на сторонние проекты и репозитории в файлах сборок. Ссылки на официальную документацию в шаблонах курсов — допустимы.
9. **Языки сборок:** `builds/ru` — русский, `builds/en` — английский; не смешивай языки в одной сборке. Термины, идентификаторы и код — как в оригинале.

## Как проверять изменения

Перед коммитом:

1. **Скиллы:** в каждой сборке 6 папок; у каждого `SKILL.md` имя = папка, есть `description` на русском ≤1024, `metadata.version`, пять разделов в правильном порядке.
2. **Шаблоны:** для каждого языка пара `COURSE.md`/`COURSE_PROGRESS.md` согласована (темы = чек-лист, `Сейчас` = первый непройденный), строка `Практика: …` на месте.
3. **OpenCode:** в temp-проекте с копией `.opencode` — `opencode debug config` (должен быть `default_agent: student`), `opencode debug agent student` (правила применяются, включая `course-plan` и `topic-lesson`), `opencode debug skill` (6 скиллов).
4. **pi:** в temp-проекте с копией `.pi` — `pi -p --approve "я застрял"` даёт «Подсказка 1 из 4». При включённом guard запись файлов требует подтверждения, в неинтерактивном режиме блокируется — это ожидаемо.
5. **Ссылки:** все относительные ссылки в markdown ведут на существующие файлы.
6. **Английские сборки:** в `builds/en` не должно быть кириллицы (кроме кода и цитат, где это неизбежно) — проверяется поиском по `[а-яё]`.

## Правила работы

- Не переименовывай скиллы, файлы курса и пути установки без необходимости: на них ссылаются персона и README.
- Меняешь поведение — обновляй README сборки, студенческий README внутри неё и корневые README (русский и английский).
- Английские сборки в `builds/en/` — полные копии русских: меняешь скилл, персону или шаблон в одной языковой версии — внеси соответствующее изменение и в другую (переводы синхронизируются вручную).
- Инсталлятор (планируется, Python, macOS/Linux/Windows) должен только копировать выбранную сборку в проект; не переноси в него логику наставника.
- Коммиты — коротко и по-русски, в повелительном наклонении: «Добавить…», «Поправить…», «Обновить…».
